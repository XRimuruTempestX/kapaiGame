# 游戏登录系统策划案

## 1. 设计目的
提供玩家安全、顺畅、便捷的进入游戏途径，保障玩家账号数据与资产安全。同时满足国家相关合规要求（如实名认证、防沉迷系统、隐私协议签署等），并为后续的用户运营留存提供基础。

## 2. 核心流程设计
1. **启动游戏**：进行基础化初始化，检查网络状态，拉取并检查游戏热更新。
2. **加载登录界面**：系统自动判断本地是否存在历史登录记录。
    - **有记录且Token未过期**：尝试自动登录 -> 成功则直接获取服务器列表/进入游戏。
    - **无记录或Token已过期**：展示常规登录UI，等待玩家操作。
3. **玩家操作**：必须先勾选《用户协议》与《隐私政策》 -> 选择对应的登录方式。
4. **身份验证**：服务器验证身份信息 -> （若为首次注册，则强制进入实名认证流程） -> 拉取玩家角色数据 -> 进入游戏主界面。

## 3. 登录方式设计
### 3.1 游客登录 (Guest Login)
- **定位**：降低新用户的体验门槛，实现“即开即玩”。
- **限制与引导**：游客账号数据绑定于设备，清理缓存或更换设备易导致数据丢失。需在玩家升到特定等级或进行充值操作前，强引导其“绑定正式账号”。
### 3.2 手机号+验证码登录 (Mobile/SMS)
- **定位**：目前国内最常用的主流登录方式，便捷且天然具备一定的实名属性。
- **流程**：输入手机号 -> 点击获取验证码（有60秒倒计时限制） -> 验证通过即登录（若手机号未注册则后台自动完成注册）。
### 3.3 账号密码登录 (Account/Password)
- **定位**：传统的登录方式，满足部分老玩家或多账号管理需求。
- **附属功能**：需配套“忘记密码”找回流程（通常通过绑定的手机号或邮箱找回）。
### 3.4 第三方授权登录 (Third-Party Auth)
- **支持渠道**：微信 (WeChat)、QQ、Apple ID（iOS端强制要求）、TapTap等。
- **流程**：拉起第三方应用授权 -> 授权成功后返回游戏 -> 绑定手机号（合规要求） -> 登录成功。

## 4. 界面UI与交互需求
- **视觉背景**：使用游戏核心视觉图（精美原画或动态CG），角落需包含当前游戏客户端版本号。
- **核心UI元素**：
    - **游戏Logo**：位于界面顶部居中或视觉重心位置。
    - **登录操作区**：位于中部偏下，包含各登录方式的入口按钮。
    - **协议勾选区**：包含复选框及超链接：“我已详细阅读并同意 [《用户协议》] 与 [《隐私政策》]”。
    - **边缘功能键**：适宜放在屏幕四角，如【客服】、【修复客户端】、【游戏公告】、【语言切换】等。
- **交互反馈**：
    - 所有按钮点击需有音效反馈及UI按下态表现。
    - 点击登录后，需有“正在连接服务器...”的 Loading 遮罩提示，屏蔽底层其他按钮的点击，防止重复发送请求。

## 5. 异常情况与提示语 (Tips)
| 异常场景 | 提示语 / 处理方式 |
| :--- | :--- |
| 网络未连接 | 弹窗提示：“网络连接失败，请检查您的网络设置后重试。” |
| 账号或密码错误 | 飘字提示：“账号或密码错误，请重新检查。” |
| 未勾选协议即点击登录 | 视觉反馈：抖动协议文本区域，并飘字提示：“请先阅读并勾选同意《用户协议》与《隐私政策》” |
| 服务器维护中 | 弹出带有关闭按钮的【维护公告】面板，详细说明维护原因及预计开服时间。 |
| 账号被封禁 | 弹窗提示：“您的账号涉嫌违规，已被限制登录。解封时间：[YYYY-MM-DD HH:MM]”，并附带【联系客服】按钮。 |

## 6. 合规与安全需求 (非常重要)
- **实名认证与防沉迷**：严格接入国家新闻出版署实名认证系统。未成年人仅在法定时间段（如周五、周六、周日及法定节假日 20:00-21:00）可登录游戏。
- **数据传输加密**：所有密码、Token、手机号等敏感信息，在客户端与服务器传输过程中必须进行非对称加密处理（如RSA+AES），严禁明文传输。
- **敏感词过滤**：玩家如果在注册阶段需要自行输入昵称，必须经过本地与服务器的双重敏感词库校验。
